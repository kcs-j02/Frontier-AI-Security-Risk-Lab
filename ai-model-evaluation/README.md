# Gemma 3 / Qwen 3 セキュリティ分析比較

## 目的

UbuntuのOllama上でGemma 3（4B）とQwen 3（4B）に**同一の根拠資料**を与え、ネットワーク・SSH・IDORの判断を比較する。NTTドコモビジネスの内部モデルやCRX機能の再現ではない。

## 実験前に

```bash
ollama list
ollama pull qwen3:4b
```

`gemma3:4b` も未導入なら `ollama pull gemma3:4b` を実行する。

`run_comparison.py` はPython標準ライブラリだけで動作する。既定ではそれぞれ3ケースを3回ずつ実行するため、**合計18試行**。実際のモデル応答はUbuntu上で生成されるため、このリポジトリには架空の評価結果を登録しない。

```bash
cd ~/Frontier-AI-Security-Risk-Lab/ai-model-evaluation
python3 run_comparison.py
```

動作確認で1回ずつ試す場合：

```bash
python3 run_comparison.py --repeats 1
```

出力は `results.jsonl`。各行に時刻・モデル名・ケース名・入力・回答・所要時間・エラーを保存する。**AIの正解率は自動で断定しない。** 回答を読んで採点し、根拠に基づく記述と未検証の推測を分ける。

## 3つの評価ケース

1. SSH設定：パスワード認証が有効という設定だけで侵害・到達性を断定しないか。
2. ネットワーク経路：同一LANのWindows→Ubuntu通信が通常pfSenseを経由しないことを理解できるか。
3. IDOR：認証ユーザーAがBの買い物カゴをHTTP 200で取得した事実を認可不備として特定し、サーバー側所有者検証を提案できるか。

## 評価基準（人手で採点）

各ケースについて各試行を以下の観点で **0 / 1 / 2 点**で採点する。

| 指標 | 0点 | 1点 | 2点 |
|---|---|---|---|
| 事実の正確性 | 主要結論が誤り | 一部のみ整合 | 実測と整合 |
| 根拠・不確実性 | 未観測事項を断定 | 区別が不十分 | 実測・推測を区別 |
| 対策の妥当性 | 無効・誤解を招く | 部分的に有効 | 原因に対応 |
| 次の検証の適切さ | 不要・不適切 | 一部有効 | 再現可能な検証を提示 |

採点者、採点日、試行ID、4指標の点数、判断根拠・引用箇所を別途記録する。モデル間の比較ではケース別結果と試行間のばらつきを併記する。3ケース×3回は探索的な比較であり、一般的なモデル性能を示す統計的な評価ではない。

## 注意事項

- 認証情報・個人情報・実環境の機密ログを入力しない。
- 本プログラムはOllamaのローカルAPI（127.0.0.1:11434）だけに接続する。
- エラー応答も記録するため、試行回数と成功回数は分けて集計する。
- `results.jsonl` を公開するときは、入力・応答に秘密情報が含まれないことを確認する。
